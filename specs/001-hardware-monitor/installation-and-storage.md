# 安装、升级与存储设计

日期：2026-10-01。对应 spec US7、FR-017～020；当前为设计，尚无可下载安装包。

## 用户安装流程

复制执行公开的一行安装命令 → 自动下载/校验预编译包 → 经管理员授权安装到 `/Applications/Cloud Mac Monitor.app` → 完成可能的系统首次批准 → 创建账户 → 自动进入本机网页。当前命令尚未实现/发布，流程详见 [free-command-install.md](free-command-install.md)。

首版发布版本化归档包、安装器及校验清单；安装器在写入系统目录及注册LaunchDaemon时请求管理员授权（终端流程使用sudo）。提供一个 Apple Silicon arm64 版本，程序启动时识别具体芯片与传感器能力。应用包内含编译后的采集服务、原生控制端、静态网页、三种语言资源及必需动态库；用户不安装 Node、Swift 工具链、Homebrew、数据库或 Docker。

首选免费ad-hoc代码签名包，不要求维护者购买Apple会员；它不提供Developer ID发行者信任，也不等于公证。首次启动被拦截时提供应用特定批准引导，不关闭Gatekeeper或自动移除隔离属性。Developer ID、公证及DMG仅作为可选后续发行渠道。[Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)、[发行打包说明](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)。

### 首次启动向导

1. 检查安装位置、系统支持情况和系统数据目录与绑定的服务所有者。校验安装路径及服务身份，不从下载暂存目录注册后台项目；可选DMG渠道直接运行时才引导复制。
2. 语言默认匹配系统/浏览器，可切换简体中文、繁体中文、英语。页面从本地资源加载，断网也能完成本机设置。
3. 打开本机账户创建页；本地原生控制端经服务所有者控制通道取得的短效 setup 授权和账户唯一性检查共同保护首次创建。用户名/密码只需设置一次，不要求邮箱。
4. 首次安装经管理员授权默认开启“开机自动启动服务”，引导显示开关及系统批准状态；创建完成后进入本机概览。局域网访问独立设置，仍默认关闭。用户关闭自动启动或系统尚未允许时，允许在系统许可范围内手动启动本次服务，只有服务已获授权并成功运行时才能创建账户；管理员授权被取消或服务启动失败时明确显示安装未完成，不回退成用户级服务。

应用重复打开时连接已有服务，并展示“打开监测页面 / 局域网访问 / 开机自动启动 / 检查更新 / 停止监测 / 清理数据”。控制窗口关闭后退出控制端，采集服务持续运行，系统1秒/应用4秒；不额外常驻浏览器壳。若未来增加常驻菜单栏进程，必须纳入现有资源预算。

### 端口、权限与后台运行

本机优先使用8765，被占用时由系统分配可用端口，由控制端取得实际地址并打开浏览器，不要求普通用户修改配置。服务身份通过绑定的服务所有者UID、根保护安装路径及受限本地控制通道确认，不把占据同一端口的陌生服务当成已运行实例。端口改动会改变浏览器 origin，允许要求重新登录，账户仍保存。

用户开启 LAN 时优先8766，冲突自动选择端口并同步地址/二维码；主机名或IP变化同样同步引导。LAN 仅在账户设置完成后可开启。后台任务位于system域，以指定普通服务所有者UID运行，与桌面登录无关；数据和TLS秘密位于系统专用目录，管理员授权的本机工具负责开机启动开关，关闭后不得在下次开机/升级偷偷重新启用。系统拒绝或要求批准时显示实际原因和对应操作入口；首版固定system plist方案不冒用SMAppService登录项状态。图形管理经NSAppleScript管理员授权调用固定维护工具，G4提前实测，详见 [launchdaemon.md](launchdaemon.md)。

默认本机监测不请求完整磁盘访问、辅助功能或常驻 root 服务；传感器能力不足按 spec 降级。企业策略、安装目录权限及系统网络权限可能要求用户确认，不能承诺所有 Mac 零提示安装。应用和任务使用系统目录及根保护所有权，纳入安装/升级验证。

## LaunchDaemon 自动启动与服务生命周期

用户已明确采用系统域LaunchDaemon：macOS启动且数据卷可用后自动运行，退出Mac登录也继续；无需用户登录桌面或监控网页。锁屏且系统唤醒时继续采集，睡眠暂停；FileVault等待解锁时不承诺第三方服务运行。自动启动不弹浏览器，不改变Web认证。

安装器经管理员授权写入 `/Library/LaunchDaemons/org.cloudmacmonitor.agent.plist`，首版采用system域任务直接注册，不再使用用户LaunchAgent。业务进程通过UserName以指定普通用户身份运行，保持单个采集/Web服务；系统启停/升级/卸载才运行按需特权工具，不增加常驻root网络服务。

新安装bootEnabled默认true，重装/升级保留用户及系统禁用选择。需要管理员授权的管理操作取消时不改状态；system任务启用、加载和进程健康分别显示。异常退出使用launchd节流与失败熔断；service disable只关闭后续开机加载并保留本次运行；start仅启动已启用任务，enable启用并启动。stop先禁用、prepareStop限时刷盘就绪后再bootout，避免被立即拉起。仅关闭窗口/浏览器不会停止采集。

完整的路径权限、服务所有者绑定、无GUI依赖、TLS文件、迁移、更新及验收见 [launchdaemon.md](launchdaemon.md)。设置开关名称为“开机自动启动服务”，从本机授权操作；不开放远程修改系统任务的接口。

## SQLite 与数据位置

用户已确认保存整机30天、应用摘要7天，首版采用随.app内嵌的SQLite，不需要用户安装或配置数据库。详细分级精度、批量写入和崩溃边界见 [history-storage.md](history-storage.md)。

| 数据 | 位置 | 行为 |
| --- | --- | --- |
| 近期系统样本及应用排行帧 | 有界共享内存 | 最近五分钟优先读取、最多一分钟衔接余量；分钟聚合可同时已落盘 |
| 30天系统桶、7天应用摘要 | history.sqlite | 每60秒批量提交系统记录，5分钟应用摘要随事务提交 |
| 唯一账户、密码验证值、配置、设备资格 | state.sqlite | 仅变更时事务保存；不保存明文密码 |
| TLS私钥 | `/Library/Application Support/CloudMacMonitor/secrets/` | 受限文件，不依赖用户登录钥匙串 |
| 12小时账户会话 | 有界内存 | 服务重启重新登录 |
| 语言偏好 | 浏览器本地存储/原生设置 | 未登录也可选择，无账号同步要求 |

两个库放`/Library/Application Support/CloudMacMonitor/data/`，root保护父目录，data属于服务所有者且0700，文件和旁文件0600，不能放.app内；不依赖HOME。初始化、建表、schemaVersion迁移由程序完成；FULL同步、并发唯一账户检查、错误恢复和会话撤销详见data-model与HTTP契约。

账户创建/修改使用Argon2id密码验证值；计算只发生在认证动作，参数和盐随PHC串保存。状态库损坏不能自动当作首次启动；历史损坏可单独隔离。迁移前按SQLite一致备份方法保留1份受同等权限保护的备份，成功后清理；空间不足不启动迁移。恢复账户备份撤销旧会话并要求本机重新确认LAN设备，不悄悄恢复已撤销资格。

重装/升级保留已提交历史和账户；清理界面把“仅清空历史”和“删除全部本机数据”分开。用户无需知道SQLite文件名、执行SQL或手工备份才能正常使用。

React、TypeScript、Vite只参与前端开发/构建，生产静态资源随应用分发；安装后的Mac无需Node或Vite服务。

## 手机首次接入的实际边界

本机安装完成后再从应用点“连接手机”：显示证书指纹和逐步指引 → 在客户端安装并信任本机证书 → 扫描一次性配对二维码 → 输入同一账户凭据登录。

保留 spec 已要求的配对与登录，不偷偷改成扫码即免密码。自动发现网络地址、生成证书和配对凭据均由应用处理。不能声称扫码就能绕过操作系统的证书信任：iOS 手动安装的证书还需要在系统设置中开启相应信任。[Apple 证书信任说明](https://support.apple.com/en-us/102390)。

该流程仍需 Safari/iOS 和桌面浏览器实测。提供短步骤图示与常见失败反馈；本机使用不受手机设置失败影响。卸载 Mac 应用不能自动清除手机信任，清理向导须提示如何移除其专用证书。

## 更新与卸载

首版提供按需“检查更新”及复制指定版本安装命令，用户通过同一公开安装器、管理员授权后升级；更新源使用HTTPS，校验发布包和ad-hoc签名，已有独立维护者发布签名时同时校验。断网只影响安装/检查更新，本机监测继续工作。不引入常驻更新轮询；Sparkle和公证更新为可选后续渠道。[Sparkle 官方说明](https://sparkle-project.org/documentation/)。

更新先验证并完整下载，再协调停止 Agent、替换应用、执行版本化状态迁移，最后按launchdaemon状态表恢复；原本关闭自启动但仍在运行的服务升级停机后保持关闭且停止，安装器提前提示，需用户主动enable恢复；保持相同应用标识和稳定安装位置。必须验证内嵌服务与安装器的生命周期，不能假定只关闭控制端就能安全替换。状态迁移失败保留备份并展示图形化恢复入口；应用文件回滚须检查schema兼容性；不能用旧数据库覆盖升级后新增记录，不兼容时保留现场并进入恢复。

在“停止并清理”中经管理员授权取消系统后台注册、退出 Agent、关闭端口；默认保留设置，用户可显式选择删除本机账户、历史、配对记录、证书密钥和日志。应用包由管理员安装，图形清理工具应在相同授权操作内删除固定应用包，或明确提示移入废纸篓可能再次要求管理员授权。直接拖入废纸篓不等于立即停止已运行服务，也不保证清除应用数据；在帮助中给出恢复/清理方式，不声称能够自动捕获所有外部删除行为。

## 开源发行

首选预编译应用及开源一行安装器，无需Apple付费发行身份；公证DMG为可选后续渠道。费用、证书类型和发布流程见 [signing-and-open-source.md](signing-and-open-source.md)。

历史管理语义见 [history-storage.md](history-storage.md)：暂停保存仍保留近期实时曲线，恢复不补写；清空同时清除已保存历史、近期曲线及待写队列，保留当前实时值和暂停设置。控制端清空确认文字必须表达该范围，不能让用户误以为只删SQLite文件。
