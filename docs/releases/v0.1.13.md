# Mac Monitor v0.1.13

This release adds in-app update installation and renames the protected installation directory to `MacMonitor`, with automatic migration of existing installations.

## Changes

- Add **Install update** after checking for updates. The app downloads and verifies the package, requests macOS administrator authorization, and reopens the updated app.
- Place progress indicators beside the corresponding update buttons and show update errors in the same section. Failed or canceled operations can be retried.
- Offer stable releases only and keep the background service running when the old control app exits after an update.
- Bundle the installer with the app and reuse its checksum, ownership, path, and package-signature checks.
- Use `/Library/Application Support/MacMonitor` for the app and its data. Existing `CloudMacMonitor` installations migrate during installation, preserving account and history databases, certificates, ownership, and service-start preferences. Saved data from an uninstalled older app can also be migrated during reinstallation.
- Preserve the managed Applications entry and the existing service identity. Conflicting directories or unsafe paths stop installation for review.

## Installation

Use the [installation commands in the README](https://github.com/cloudshadow/mac-monitor/blob/v0.1.13/README.md#install), or download the package for your architecture, `install.sh`, and the checksum files below.

Older app versions only provide an installation command; use that command or the README instructions once to upgrade to v0.1.13. After the manual upgrade, quit and reopen Mac Monitor. Subsequent updates can be installed from within the app. Do not rename the existing installation directory manually.

Packages are provided for Apple Silicon (`arm64`) and Intel (`x86_64`) on macOS 14 or later. Apple Silicon is the target platform; the Intel package is available for development testing. The app uses ad-hoc signing and may require macOS first-launch approval. Installation requires administrator authorization.

## Validation

- 49 Swift tests, including update progress, duplicate-action prevention, failed-install retry, installer failure reporting, and service preservation during relaunch.
- Installer tests for directory migration, account/history/certificate preservation, service preferences, reinstallation, unsafe paths, GUI authorization handoff, argument quoting, canceled authorization, and checksum rejection.
- Production web build, TypeScript and localization checks, seven Chrome browser tests, and two mobile WebKit layout tests.
- HTTP, port configuration, and LAN HTTPS smoke tests.
- Both package architectures, signatures, bundled installers, versions, and SHA-256 checksums verified. GUI authorization handoff was tested without elevation; privileged installation and Intel runtime were not exercised on this machine.
