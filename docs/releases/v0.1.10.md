# Mac Monitor v0.1.10

This release fixes failed page loads when accessing Mac Monitor over LAN HTTPS from a phone.

## Fix

Browsers open multiple HTTPS connections in parallel to load scripts, styles, translation files, and API responses. The server previously allowed only two pending TLS handshakes, closing additional connections during normal page loading. This could leave the page full of loading labels and show "Something went wrong. Please retry."

TLS handshakes now share the existing limit of 16 total connections. The five-second handshake timeout and overall connection limit remain enforced.

Update Mac Monitor on the Mac, then reload the dashboard on your phone. Reloading the phone alone does not update the server.

## Installation

Use the [installation commands in the README](https://github.com/cloudshadow/mac-monitor/blob/v0.1.10/README.md#install), or download the package for your architecture, `install.sh`, and the checksum files below.

Packages are provided for Apple Silicon (`arm64`) and Intel (`x86_64`) on macOS 14 or later. Apple Silicon is the target platform; the Intel package is available for development testing. Updates preserve your account, history, certificates, and service-start preferences.

The app uses ad-hoc signing and may require macOS first-launch approval. Installation requires administrator authorization. Sensor availability depends on the Mac model and drive connection.

## Validation

- 47 Swift tests, including parallel TLS admission and the total connection limit.
- Seven browser tests, including repeated cold mobile page loads, refreshes, login, and live data connections over real LAN HTTPS.
- LAN HTTPS authentication, session isolation, and revocation smoke checks.
- Package signatures, versions, and SHA-256 checksums for both architectures.

The new HTTPS page-load regression fails with the previous server and passes with this fix. Browser automation does not replace physical iOS/Android certificate-trust acceptance.
